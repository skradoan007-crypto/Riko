# Waveform correction after device feedback

The prior full-song filled envelope was a static area plot, not the requested flowing ribbon. Its display was gated on full-file analysis. The supplied device report showed over a minute with a bare rail. This update changes the foreground visualization deliberately: it is now a real-audio-driven live ribbon, not a claim that moving ribbon geometry is a fixed timestamp plot.

The existing playback PcmAudioProcessor amplitude is sampled only inside the visible playing timeline's frame loop. Nine fixed reusable membrane slots (three per layer) transport smooth, bounded crests from circle to left. Heights come from filtered actual PCM energy; silence emits nothing. There is no random data or sine oscillator. The three layers have separate smoothing, lifetimes and emission spacing. Paths are reused with 64 bounded cubic segments per layer; there are no per-frame large collections, shader allocations, microphone capture or new dependencies.

Offline real full-song analysis and its versioned cache remain separate. They no longer gate the live playing foreground; the stable cached envelope is used for seek inspection, paused no-history fallback and reduced-motion display. During playback, first response depends on real PCM becoming available, not analysis completion. No measured startup-time guarantee is made. The old documentation describes the earlier implementation; this correction supersedes its foreground-rendering description.

Pause/hidden/background stops transport, preserving the last live shape. Track changes and seek discontinuities reset transport. The whole ribbon remains clipped at the seek circle. The existing single ExoPlayer and seek commit/reconciliation remain intact. Decoder polling now uses nonblocking input/output when work is progressing instead of routinely waiting on both queues.

Validation prepared: pure Kotlin AudioRibbonFlowTest covers silence, early audio response, left travel, bounds, independent layers, pause and reset. The production Compose render test additionally supplies live amplitude with null offline data, saves render evidence and checks pause stability. These tests need CI execution. No device animation, pixel-match claim, frame timing or startup latency has been verified here. Existing PCM tap capability remains required; if a device/format produces no PCM, the app cannot honestly manufacture live musical response.
