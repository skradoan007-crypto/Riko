2. Every Feature — Real Behavior
Equalizer (EQ) Bands
Location: Top of main screen, scrollable vertical list. Number of bands = 5 or 10 (determined by device capability, stored in kf.f.n()).

How to use:

Scroll up/down to view all bands
Each band has: ArcSeekBar (slider) + TextView showing frequency label (top) + TextView showing gain value (bottom)
Drag slider left/right to adjust gain
Default state (EQ off):

All band gains at 0 dB
Sound is flat/neutral per original audio source
Enabled (EQ on via sw_eq):

Active processing begins immediately
Gains from current preset are applied
Level changes:

Each band ranges approximately -12 to +12 dB (exact range depends on device; text_slider layout shows top/bottom labels)
Increasing a band boosts that frequency range
Decreasing cuts that frequency
Maximum (+12/+15 dB):

Strong emphasis at that frequency
Can cause muddiness if multiple bands boosted simultaneously
May introduce clipping depending on source volume
Minimum/Off (0 dB):

No change to that frequency
Bypass mode for that band
Sound character:

Low bands (~32-60 Hz): Kick drum, bass guitar depth
Mid bands (~150-800 Hz): Vocals, presence
High bands (~2-4 kHz): Consonants, clarity
Very high bands (~8-16 kHz): Air, cymbals, detail
Best use case:

Correcting problematic source recordings
Tailoring sound to headphones/speakers
Enhancing specific instruments
Bad/extreme use:

All bands boosted → muddy, distorted, potential clipping
Extreme boosts on adjacent bands → phase issues, unnatural sound
Interaction with other effects:

EQ + Bass Boost: additive low-end boost
EQ + Loudness: combined tonal balance and volume increase
EQ + Virtualizer: spatial widening + frequency emphasis
Reset behavior:

Reset button (toolbar restartBtn) returns all EQ bands to 0 dB
Does NOT reset Bass Boost, Loudness, Virtualizer, Reverb
Persistence:

EQ state (on/off + band values) saved per-preset
App restart: restored from currently selected preset
Bass Boost
Location: First control card below EQ bands. Contains sb_bass_boost (ArcSeekBar), sw_bass_boost (JSwitch), tv_bass_boost_gain (gain value display), tv_bass_boost_title.

How to use:

Toggle switch ON/OFF to enable/disable
Drag slider to adjust boost level
Default state (off):

Bass boost bypassed
Low-end remains at source level
Enabled:

Low-frequency emphasis applied
Uses Android BassBoost API with configurable frequency and max gain
Level changes (slider 0-100%):

0% (minimum): Bass boost disabled, gain display shows "0 dB"
25%: Subtle low-end warmth, slight fuller sound
50%: Noticeable bass boost, kick more present, low-end more prominent
75%: Strong bass emphasis, low-end dominant, may overwhelm mids
100% (maximum): Maximum bass boost per configured bass_boost_max_gain (default 15dB) and bass_boost_freq (default 80Hz, configurable)
Sound character:

Increased punch and impact of kick drum
Bass guitar becomes more prominent
Low-end becomes "thicker" and more dominant
May reduce perceived vocal clarity if overdone
Best use case:

Music genres: hip-hop, EDM, pop where enhanced low-end is desired
Headphones that lack natural bass response
Casual listening where more "fun" sound is preferred
Bad/extreme use:

Maximum setting on speakers → boomy, muddy bass, potential distortion
Combined with EQ low-band boosts → cumulative effect, possible clipping
Voice-heavy content (podcasts, audiobooks) becomes bass-heavy and less clear
Interaction with other effects:

Bass Boost + EQ low bands: cumulative bass increase
Bass Boost + Loudness: combined low-end + overall loudness increase
Bass Boost + Virtualizer: wider stereo image with enhanced bass
Bass Boost + Reverb: more spacious low-end
Reset behavior:

EQ reset does NOT reset Bass Boost slider/switch
Bass Boost can be individually toggled off or slider returned to 0
Persistence:

Saved per-preset (bb_slider + bb_switch values in CustomPreset)
App restart: restored from current preset
Configuration (from source code):

Default bass boost frequency: 80 Hz (configurable via bass_boost_freq shared preference)
Default max gain: 15 dB (configurable via bass_boost_max_gain shared preference)
When com.zipoapps.premiumhelper.d.a.a().f11604d.i() is true (Pro version), these values are read from preferences; otherwise hardcoded to 80 Hz and 15 dB and the value is written to preferences

6. Sound Quality — Deep Analysis
Equalizer Processing
Gain handling:

Each EQ band gain stored as integer value, converted to Float for Android Equalizer API
Values mapped to device-specific band cutoff frequencies
Band count is device-dependent: kf.f.n() returns 5 or 10
Band values stored in CustomPreset.slider List
Clipping prevention:

The code does not appear to have built-in gain normalization across bands
Multiple bands boosted simultaneously can exceed headroom
Service uses dynamicsProcessing (DynamicsProcessing API) with pre/post EQ
Limiter configured via m0.f52377j with preferred frame duration iG
Post-EQ cutoff frequencies adjustable via listD values from kf.a.d(iJ)
Normalization:

No track-level normalization appears in the audio processing chain
Loudness control (LoudnessEnhancer) provides some perceived loudness normalization
Dynamics Processing configured with Config.Builder using parameters from kf constants
Limiter:

DynamicsProcessing includes limiter per channel
Post-gain settable via limiterByChannelIndex.setPostGain(f10) where f10 derived from kf.f.a() (reference gain value)
Limiter appears active when zD (channel balance switch) configuration is enabled
May engage automatically based on kf.f.d() (Dynamics Processing switch)
Headroom:

Dynamics Processing configured with i13 = 2 when zD true, or i13 = 1 when false
This affects how much headroom is allocated before limiting engages
When zD false: 1:1 ratio; when true: 2:1 ratio (more aggressive limiting)
Band interaction:

EQ bands can interact when multiple boosted simultaneously
No automatic "smart" EQ - user controls each band independently
Dynamics Processing post-EQ may reduce overall level if pre-EQ too hot
Effect ordering (from code analysis):

Pre-EQ (DynamicsProcessing getPreEqByChannelIndex(0)) - adjusts signal before main processing
Main processing chain (BassBoost, LoudnessEnhancer, Equalizer, Virtualizer, Reverb)
Post-EQ (DynamicsProcessing getPostEqByChannelIndex(0)) - adjusts signal after main processing
Limiter on each channel
This ordering means:

EQ shaping happens before Bass/Loudness/Virtualizer/Reverb
Final limiting ensures output doesn't exceed safe levels
Pre-EQ can sculpt the signal before any enhancement
Optimization Benefits
Dynamics Processing (when enabled via zD):

Problem solved: Prevents clipping and maintains consistent output level
User benefit: Sound remains clean even at high gain settings; reduces distortion risk
Sound quality effect: Smoother output, less likely to distort with extreme EQ boosts
Downside: May reduce perceived dynamic range; limiting can feel "compressed" if set too aggressively
Bass Boost frequency/configuration:

Problem solved: Configurable frequency avoids boosting wrong frequency range; max gain prevents overboosting
User benefit: More controlled bass, less muddy when configured properly
Sound quality effect: Tighter, more controlled low-end when frequency set appropriately for content
Downside: If frequency set wrong for content, may not enhance desired frequencies
Loudness max gain:

Problem solved: Configurable ceiling prevents excessive loudness
User benefit: Can increase volume without distortion risk
Sound quality effect: Consistent perceived loudness across content
Downside: May still reduce dynamic range if used excessively
Equalizer band count adaptation (5 vs 10 bands):

Problem solved: Fewer bands (5) on devices with limited DSP resources; 10 bands on capable devices
User benefit: More precise control on supported devices; lighter processing on others
Sound quality effect: 10-band allows more surgical frequency shaping; 5-band is broader strokes
Downside: 5-band may miss problem frequencies that 10-band would catch
Audio session handling:

Service runs as foreground with persistent notification
Properly detaches from audio when no music playing
Reloads effects when new track/device detected
Benefit: No stale processing; effects always match current content
Service lifecycle management:

Service stops when no active audio session + only_music_player not enabled
Prevents processing silence or non-music audio
Benefit: No unnecessary processing; battery-friendly; no coloration of non-audio audio

9. Combinations
EQ + Bass Boost:

Both affect low-frequency range
Additive: combined boost can be significant
Example: EQ low band +6 dB + Bass Boost 50% = substantial bass increase
Risk: Clipping if both maxed, especially with loud source material
Useful for: Genres where enhanced bass is desired (hip-hop, EDM)
Caution: Monitor for muddiness or distortion
EQ + Virtualizer:

EQ shapes tone, Virtualizer adds spatial width
Generally complementary: EQ can make room for Virtualizer by cutting conflicting frequencies
Example: EQ boost vocals (+3 dB at 2 kHz) + Virtualizer 50% = vocals more present + wider instrument backing
Caution: Extreme EQ + extreme Virtualizer may cause phase issues, thin sound
EQ + Reverb:

EQ can tame problematic frequencies that reverb might exaggerate
Example: EQ -3 dB at 8 kHz + Reverb 50% = reduced harshness with added space
Caution: Boosted high frequencies + reverb = sibilance and harshness
Useful for: Making vocals or instruments sound "in a space" with controlled tonal balance
Bass Boost + Loudness:

Combined low-end emphasis + overall volume increase
Makes quiet content feel "fuller" and louder
Example: Bass Boost 75% + Loudness 50% = noticeable loudness increase with enhanced bass
Caution: Risk of clipping with already-loud source material
Useful for: Quiet listening situations where more bass and volume desired
Bass Boost + Virtualizer:

Enhanced low-end + widened stereo image
Can make bass elements feel both heavier AND wider
Example: Bass Boost 100% + Virtualizer 75% = very wide, very heavy low end
Caution: May cause phase issues; bass may feel "all over the place" rather than centered
Useful for: Creative effect in certain electronic music genres
Preset + Manual adjustment:

Loading a preset replaces all current settings
Subsequent manual adjustments override preset values for active bands
Example: Load "Vocal" preset, then boost EQ mid band +3 dB = vocal preset + extra mid emphasis
To return to preset: Reset EQ bands (restart button)
Useful for: Starting from a base preset and fine-tuning for current content
All effects ON simultaneously:

EQ + Bass Boost + Loudness + Virtualizer + Reverb + Channel Balance
Can create very colored, heavily processed sound
Example: 10-band EQ boosted + Bass Boost 100% + Loudness 100% + Virtualizer 100% = extreme sound transformation
Caution: Very high risk of clipping, distortion, ear fatigue
Useful for: Creative/special effects, not for critical listening

Overprocessed combinations to avoid:

All EQ bands boosted + Bass Boost 100% + Loudness 100% = almost certain clipping
Extreme EQ + Extreme Virtualizer + Reverb = phase mess, thin harsh sound
Bass Boost + EQ low bands + Reverb = boomy, muddy, indistinct
10. "Best Settings" Type Insights
Based on implementation behavior and typical use cases:

Clean bass (tight, controlled low-end):

EQ: Flat or slight low-mid boost (+3 dB at 100-200 Hz)
Bass Boost: ON, slider ~30-40% (not maximum)
Loudness: OFF or low (~20-30%)
Virtualizer: OFF
Reverb: OFF
Channel Balance: Center
Why: Bass Boost with moderate slider + gentle EQ boost provides enhanced bass without overwhelming. Maximum Bass Boost + max EQ = muddy.
Strong bass (fun, impactful):

EQ: Boost low bands (+3 to +6 dB at 60-150 Hz)
Bass Boost: ON, slider 75-100%
Loudness: ON, slider 30-50% (adds perceived volume)
Virtualizer: OFF or low (25%) (wideness helps perceived bass)
Reverb: OFF
Channel Balance: Center
Why: Combines EQ targeting + Bass Boost amplification. Good for hip-hop, pop on headphones.
Vocal-focused (clear, present vocals):

EQ: Boost upper-mid (~+3 to +6 dB at 2-4 kHz), cut low-mid if muddy (-3 dB at 250 Hz)
Bass Boost: OFF (or low ~20%)
Loudness: ON, low slider (~20-30%) (helps quiet passages)
Virtualizer: OFF (can push vocals back)
Reverb: OFF or very low (avoid washing out vocals)
Channel Balance: Center
Why: Boosting speech frequencies + reducing competing low-mud makes vocals stand out. Reverb can distance vocals.
Bright sound (detailed, energetic):

EQ: Boost upper-treble bands (+3 dB at 4-8 kHz if 10-band, or highest band)
Bass Boost: OFF (avoid adding mud to already-bright source)
Loudness: LOW (~20%) (bright sources may already seem loud)
Virtualizer: LOW (~25%) (wideness can add perceived brightness)
Reverb: OFF (reverb can reduce perceived clarity)
Channel Balance: Center
Why: Careful treble boost adds air and detail without sibilance. Too much = harshness.
Warm sound (rich, smooth):

EQ: Slight low-mid boost (+3 dB at 100-250 Hz), slight high-mid cut if harsh (-2 to -3 dB at 3-5 kHz)
Bass Boost: ON, moderate (~50%)
Loudness: LOW-MODERATE (~30%)
Virtualizer: LOW (~25%) (adds slight width without brightness)
Reverb: LOW (~20%) (adds slight room without washing)
Channel Balance: Center
Why: Low-mid boost + moderate bass + gentle reverb = "warm" character. Cutting harsh highs smooths tone.
Wide sound (expansive stereo):

EQ: Flat or slight adjustments for balance
Bass Boost: Moderate (~50%) (tight enough to maintain definition)
Loudness: LOW (~20%)
Virtualizer: 75-100% (primary width control)
Reverb: LOW-MODERATE (~30%) (spatial complement)
Channel Balance: Center
Why: Virtualizer primary for width; moderate bass maintains definition; reverb adds spatial depth.
Low-volume listening:

Loudness: ON, slider 50-100% (compensates for volume loss at low levels)
Bass Boost: ON, moderate (~50%) (low-end often perceived weaker at low volume)
EQ: Gentle boost at presence frequencies (+3 dB at 1-3 kHz)
Virtualizer: OFF or low (spatial effects may disappear at low volume)
Reverb: OFF (may disappear at low volume)
Channel Balance: Center
High-energy music (rock, electronic):

EQ: Moderate shaping - maybe slight V-curve (boost bass + treble, cut mids)
Bass Boost: ON, 50-75% (adds punch)
Loudness: ON, 30-50% (helps cut through mix)
Virtualizer: 50% (widen stereo image of production)
Reverb: OFF (studio recordings often already have space)
Channel Balance: Center
Note: These are practical interpretations based on how the controls interact, not arbitrary EQ value generation. Existing presets in user's experience would dictate actual starting points.

12. Extreme Cases
Maximum bass (Bass Boost 100% + EQ low bands +6 dB): → Behavior: Significant low-end emphasis → Sound: Very boomy, potentially muddy → Clipping risk: High, especially with loud source material → Protective behavior: Dynamics processing limiter may engage if enabled → State preservation: All values saved; switching off returns to previous non-max state → Side effect: May reduce vocal clarity, make mix sound "blown out"

Minimum bass (all off): → Behavior: No bass enhancement → Sound: Source audio as-mixed, no added low-end → State: All switches off, sliders at minimum → Persistence: Saved per-preset; app restart restores from preset

Maximum gain (Loudness 100% + EQ all bands boosted): → Behavior: Maximum possible gain increase → Sound: Likely clipping, distortion, very loud output → Clipping risk: Very high → dynamics limiter should engage if enabled → Protective behavior: DynamicsProcessing limiter configured with post-gain from kf.f.a() (reference gain) → May automatically reduce perceived level if limiter protects

All EQ bands boosted: → Behavior: Every frequency band at maximum boost → Sound: Extremely colored, likely harsh, muddy, distorted → Clipping: Inevitable with most source material → Protective behavior: Dynamics processing post-EQ may reduce overall level → User experience: Generally unpleasant; most stop before this point

Effects simultaneously enabled (all ON): → Behavior: Bass Boost + Loudness + Virtualizer + Reverb + EQ + Channel Balance all active → Sound: Highly processed, potentially unusable for critical listening → May sound "exciting" for casual listening, "muddy" for detailed content → Clipping: Very likely with loud source → Recommendation: Use sparingly, one effect at a time for best results

Rapid slider movement: → Behavior: SeekBar progress changes quickly → Sound: May hear "zipper noise" or audible artifacts if not properly smoothed → Android audiofx typically has some smoothing, but extreme changes may be audible → UI: Slider thumb follows finger, gain values update rapidly → Recommendation: Make deliberate adjustments, not rapid flicking

Enable → Disable → Enable: → Toggle Bass Boost off then on again → bbswitch toggled, service processes state change → Slider value retained from previous on state → Sound: Turns off, then re-applies with same slider position → No reset unless slider also returned to 0

Track change (new song starts): → Service detects new audio session → May reload current preset if auto_apply enabled in settings → If auto-apply disabled: Preset remains loaded from previous track → Sound: Effects continue with same settings; may need to re-adjust for new track's characteristics → Persistence: Preset state carried over unless auto-apply triggers new preset

App background → foreground (extended pause): → Service continues running in background → UI reflects last known state on return → No automatic reset or state change → Sound: Same effects continue; may be jarring if settings were for different content → Battery: Service is foreground, uses some battery; optimal to turn off when not needed

Repeatedly switching presets quickly: → Each switch loads preset values into sliders/switches → UI updates to show new preset's values → Sound: Changes instantaneously with each selection → May cause brief audio interruption during preset load → No cumulative effect; each preset starts fresh from its saved state → Caution: May be disorienting; settle on one preset for best listening
