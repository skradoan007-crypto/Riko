# RIKO DNA (MDNA) — Phase 1: production pipeline + Visualizer style

## What changed
| Area | Change |
|---|---|
| Audio thread | `PcmAudioProcessor.rawTap` (`audiofx/RawSpectrumTap.kt`): raw, UNdelayed 40-band targets at FFT cadence (~60Hz) with a nanoTime stamp. One volatile null-check per FFT pass when nobody listens; a faulty tap is detached, never breaks playback. |
| Handoff | `dna/core/SpectrumHistoryRing.kt`: timestamped SPSC ring; render thread asks for "the spectrum at `now − latency`" and gets a frame interpolated between its two neighbours. Reads are validated after the fact (lap-around → retry). |
| Latency | `dna/sync/MdnaSyncHub.kt`: latency = base (`AV_SYNC_DELAY_MS`, so MDNA lines up with the other styles) + a user offset remembered SEPARATELY for speaker/wired vs Bluetooth. |
| Renderer | Now consumes a `BandSource` (production ring, legacy buffer, demo). `QualityGovernor` steps quality DOWN when frames keep missing the display budget. |
| Integration | `SpectrumStyle.MDNA` → appears in the Visualizer style grid; `MdnaVisualizerHost` (Compose) swaps the Canvas for the GL surface; tap attached only while it is on screen. |
| Lab | DIRECT ⇄ LEGACY ⇄ DEMO source switch for A/B, sync-offset slider, auto-quality toggle, `auto↓` counter. |

Existing files touched (see `p1-existing-files.patch`): `PcmAudioProcessor.kt`, `SpectrumStyle.kt`, `SpectrumRenderer.kt`, `AuroraSpectrum.kt`.

## How to test
1. Install, play a song. Open **MDNA Lab**, Src = DIRECT. Flip Src to LEGACY and back while the song plays — DIRECT should hit on the beat and move more smoothly.
2. Adjust **Sync offset** until kicks look exactly on the sound. Do it once on the speaker and once on Bluetooth: they are stored separately.
3. Open the real app → Now Playing → Visualizer → style **MDNA**. Use the − / + nudge at the bottom.
4. Try Q = High on your phone and watch `auto↓`: if the governor drops the tier by itself, that is the phone telling you its real budget.

## What to report
- fps / ms for Low · Mid · High (bloom on) on your phone, plus the phone model + Android version.
- DIRECT vs LEGACY: which feels tighter, and the sync offset you settled on (speaker / Bluetooth).
- Anything black, an `ERROR:` line, or `auto↓` firing on a phone that should cope.

## Honest limits
- **Latency is estimated, not measured.** Media3 has no continuous output-latency reading (only a one-shot `onAudioPositionAdvancing`, an unstable API). Hence base + per-output user offset.
- Verified off-device: all `dna/**` Kotlin except the Compose host compiles on Kotlin 2.0.21 (the lab compiles against stubs of Hilt / lifecycle); 30 JVM tests pass, incl. a lap-around stress test. **Not compiled here:** `MdnaVisualizerHost` (Compose), the real Hilt wiring, and the `PcmAudioProcessor` edit (Media3) — CI is their first real compile.
- The ring's concurrency was stress-tested on a 1-core sandbox: multi-core ARM memory ordering is argued from the design (RMW barrier before validation), not exercised.
- Only the DNA Bloom scene exists. The 10-template system is P2.
