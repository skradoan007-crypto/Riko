# RIKO DNA (MDNA) — Phase 2: template system + 3 new templates

## What changed
| Area | Change |
|---|---|
| Catalog | `dna/render/MdnaTemplate.kt`: a template = shader pair + point budget + camera rule. Everything else is the shared engine. |
| Templates | **DNA Bloom** (P0/P1, unchanged look) · **Halo** · **Dot Terrain** · **Pulse Lens** |
| History | `MdnaHistoryTexture` (R8, 64 rows × 40 bands) + `HistoryClock`: the recent past as rows, pushed on a fixed TIME cadence (24/s), scrolled smoothly between pushes. Dot Terrain reads it with `texelFetch`. Reusable by the next terrain-style templates. |
| Camera | SPHERE templates now auto-fit the screen (P1's outer DNA Bloom shell was clipped on a portrait phone by my arithmetic — fixed). SCREEN templates lay themselves out from `uView`; Pulse Lens runs along the screen's LONG axis. |
| Safety | A template that fails to compile falls back to DNA Bloom and reports `templateError` — never a black screen, never a crash. |
| UI | Visualizer: ‹ template › picker at the top (remembered, `MdnaSettings`); Lab: `Tpl:` button + template/error line. |
| Seed | `uSeed` is wired through the engine (`renderer.seed`, 0 = neutral) so P5 can give every SONG its own variation inside any template. |

Existing files touched in P2: none (P1's patch is unchanged).

## Adding a template (checklist)
1. Write `foo.vert` using the common uniforms (see `MdnaShaders.kt` header); reuse `sprite_soft.frag`.
2. Validate: `glslangValidator -S vert foo.vert` and `glslangValidator -l foo.vert sprite_soft.frag`.
3. Paste into `MdnaShaders.kt`; add one `MdnaTemplate` entry (budget at MID, layers, granule, camera).
4. If the shader hard-codes a layout constant (rows, strands…), mirror it in Kotlin and extend the guard in `MdnaTemplateTest`.

## How to test
1. Open the Visualizer → MDNA, tap ‹ › at the top and cycle all four. Do the same in the Lab with `Tpl:`.
2. For each: Q = Low / Mid / High (bloom on) — note fps/ms and whether `auto↓` fires.
3. Check portrait AND landscape: Halo/DNA Bloom must stay fully on screen; Lens must run along the long axis.
4. Play something with a strong kick: Dot Terrain should flow away from you at a steady speed; Pulse Lens should pinch at the centre and flare on the beat.

## What to report
- Phone model + Android version; fps / ms per template per quality; any `ERROR:` / `FAILED:` line in the Lab.
- Which template looks closest to your reference and which one is off (colour, density, size, speed) — tell me in your own words, tuning is cheap now.

## Honest limits
- **No GPU was available here.** The four shaders pass glslang (ESSL 3.00) validation, each vertex/fragment pair links, and the Kotlin ↔ GLSL layout constants are guarded by a unit test — but none of them has been RUN on a GPU by me. `p2-preview-cpu.png` is a numpy port of the shader MATH used to catch layout mistakes (it did: Lens and Terrain were re-laid out because of it). Its brightness/glow is NOT representative.
- Point budgets (MID: DNA Bloom 4×8k, Halo 26k, Terrain 6.7k, Lens 14k) are starting guesses until your fps numbers exist.
- Verified off-device: all `dna/**` Kotlin except the Compose host compiles (2.0.21); 41 JVM tests pass. The Compose host and real Hilt wiring still first compile in CI.
